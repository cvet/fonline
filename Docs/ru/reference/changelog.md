# История изменений движка
<!-- docs-translation: {"document_id":"engine-changelog","locale":"ru","source_path":"Docs/en/reference/changelog.md","source_sha256":"8a5301b9f66b6a8929c90f0ec7de851f0df20d1527930eeedd63acdf20d8ab8a"} -->
Здесь ведутся значимые для разработчиков изменения FOnline и заметки о миграции на русском и английском. Текущую версию разработки задаёт [VERSION](https://github.com/cvet/fonline/blob/master/VERSION). [Правила версий и выпусков](../how-to/release/versioning.md) определяют CalVer, даты выпусков, неизменяемые теги и границы совместимости.

## Unreleased

## 2026.1.2-dev - 2026-10-04

### Изменено

- Движение с удержанием направления трассирует и продлевает планы, меняет их при поворотах и может скользить вдоль препятствий. Пошаговые аренды ограничивают продолжение движения на сервере и у наблюдателей при задержке связи управляющего клиента.
- Общая синхронизация движения измеряет обычное время передачи, догоняет опоздавшие планы и присоединяет план на уже пройденном шаге. Это затрагивает и движение по клику; поиск пути к выбранной точке сохраняется. Наблюдатель может плавно догонять движение вместо немедленного скачка. См. [движение](../explanation/maps-and-movement.md) и [сетевую модель](../explanation/authority-and-networking/index.md).
- Регрессионный тест хеша сборки размещает настоящие CMake helpers рядом с временным проектом и поддерживает checkout и временный каталог Windows на разных дисках.

### Миграция

- Обновите сервер, управляющие клиенты и наблюдателей вместе. `SendCritterMoveLease` и `CritterMoveLease` расширяют сетевой протокол; маркер совместимости повышен с `0.0.66` до `0.0.68`. Повторно сконфигурируйте и соберите нативные приложения и библиотеки runtime, перепеките обе стороны из одной ревизии исходников. Не обходите проверку совместимости ради смешанных ревизий. Это изменение движения не переименовывает сохраняемые свойства/прототипы и не требует преобразования сохранений.
- Проверьте новые `Network.LinkDelayWindowMs`, `Network.LinkDelayRebaseMs`, `Network.MoveLateCatchUpMinMs`, `Network.MoveLateCatchUpMaxMs` и `Network.MovePlanJoinMaxSteps` во всех затронутых конфигурациях. Смысл прежних настроек сохранён. Ищите точные ключи в исходниках конфигурации; отсутствующий ключ получает документированное значение по умолчанию. Нулевой предел присоединения отключает его.
- Проверьте новые `Client.DirectMoveTraceSteps`, `Client.DirectMoveExtendAheadSteps`, `Client.DirectMoveLeaseSteps`, `Client.DirectMoveLeaseRenewSteps`, `Client.DirectMoveRetargetMinMs`, `Client.DirectMoveRetargetImmediateAngle` и `Client.DirectMoveSlide`. Пределы продления/возобновления должны быть меньше пределов трассы/аренды. Переписывать заданные точки движения и обычные вызовы движения по клику не требуется.
- Проверьте новые `Client.MoveCatchUpRate` и `Client.MoveCatchUpSmoothMaxMs` для воспроизведения движения наблюдателем. Перегенерируйте API скриптов и справочник настроек, скомпилируйте затронутые скрипты; все четырнадцать дополнений — настройки только для чтения, а не изменяемое состояние скриптов.
- Проверьте движение прямо с удержанием направления, повороты, остановку и края препятствий управляющим и наблюдающим клиентами, затем обычные цели по клику и прерывания. Повторите с задержкой, джиттером и зависанием передачи, проверяя истечение аренды и согласование поздних планов. Для диагностики доступна прежняя `Network.MoveSyncTrace`; вне диагностических запусков она должна быть выключена. Проверка поведения и проверка производительности имеют отдельные результаты.
- В копии тестового проекта хеша сборки размещайте три настоящих CMake helper-файла рядом с ним вместо относительного пути через границу дисков. Поведение маркеров в производственной сборке не меняется.
- Перегенерируйте конфигурации MinimalMultiplayer, ContentShowcase и PackagingMatrix их владельцами `generate_config.py`, чтобы включить четырнадцать настроек движения. Реестр нативных тестов включает `Test_LinkDelay.cpp`; проверки двуязычной документации и примеров теперь учитывают две страницы политики версий.
- Потребители поиска документации должны учитывать проверенный `max_bytes` манифеста для каждой локали, повышенный с 1 835 008 до 1 867 776 байт ради полного корпуса движения/настроек и миграции. Состав документов, правила токенов и отказ при превышении лимита сохранены; лимит полного контекста для ИИ не меняется.

## 2026.1.1-dev - 2026-10-04

### Добавлено

- CalVer движка из `VERSION` проверяется при конфигурации CMake, встраивается в `FO_ENGINE_VERSION` и выводится в логах запуска нативных приложений. `FO_ENGINE_REVISION` содержит SHA Engine и отметку `-dirty` при изменении отслеживаемых файлов отдельно от хеша сборки игрового проекта.
- Ссылка версии в документации открывает эту историю изменений на выбранном языке. Данные навигации и маршрутов, а также данные для ИИ получают версию движка из того же исходного файла.
- Двуязычные заметки и проверки выпуска задают владельца значимых для разработчиков изменений и обязательных инструкций миграции.

### Изменено

- Поддержка только актуального API Engine сохраняет первоначальный смысл существующих значений. Замены удаляют старый API и обеспечивают явные ошибки компиляции/перепекания/валидации и исчерпывающие двуязычные миграции; существующее преобразование сохранённых свойств через `MigrationRule` остаётся узким исключением.
- Каждый опубликованный шаг master увеличивает minor и фиксирует год/дату UTC; релизные линии сохраняют год/major/minor среза и увеличивают patch, используя `-rc` при стабилизации. Правки только документации, CI, тесты и зависимости тоже учитываются.

- Историческая заглушка `2022.1.0.wip` в `VERSION` заменена идентификатором разработки в формате CalVer. Существующие исторические аннотации API `Since` сохраняют прежние значения.

### Миграция

- Ограничение полного контекста увеличено с 2 162 688 до 2 195 456 байт, чтобы включить полные обязательные правила обновления/миграции. Потребители данных документации учитывают объявленный `full_context.max_bytes`, а не фиксированный прежний буфер; включение документов целиком и проверка превышения лимита сохранены.

- Прежняя черновая нотация `YYYY.M.PATCH` заменена. Используйте `YEAR.MAJOR.MINOR-dev` в master и `YEAR.MAJOR.MINOR.PATCH[-rc]` в `release/YEAR.MAJOR`; major — номер линии, месяц записан в дате заметки. Первое принятие политики задаёт `2026.1.1-dev`. Потребители прежнего синтаксиса версии должны принимать эти точные формы и отвергать прежние суффиксы/окончательные трёхпольные версии; общий парсер — `BuildTools/engine_version.py`. Перед обновлением выполните [полный список обновления](../how-to/release/versioning.md#каждое-обновление-master), последовательность среза релиза и запись миграции.

- Политика версий в манифесте документации теперь использует схему версии `3` и объявляет `engine: {scheme: calver, source: VERSION, master_format: YEAR.MAJOR.MINOR-dev, release_format: YEAR.MAJOR.MINOR.PATCH[-rc]}`. Собственные потребители, перегенерирующие эти артефакты, должны включить эту политику и предоставить файл `VERSION` движка. Обновляемая документация по-прежнему соответствует `master`.
- Повторно сконфигурируйте и соберите нативные бинарники, чтобы получить идентификаторы движка. Версия игры, хеши сборок пакетов и обновления клиента, хеш совместимости выполнения, версии ABI и схем ресурсов сохраняют свои контракты; это изменение не требует миграции данных или повышения версии схемы ресурсов.
