## Current - 2026-10-10

### Исправлено

- В pull request, как и в push, проверяется каждый входящий шаг первого родителя; пропущенное повышение версии и потерянные прежние заметки остаются ошибкой.
- В integration fixture native updater конфигурации resource pack сохраняются в именованных ConfigFile перед применением настроек. Одинаковое исправление допуска к компиляции внесено в кандидат и контроль.

### Миграция

- Миграция исходников проекта или сохранённых данных не требуется: этот шаг исправляет два вызова в тесте и проверку PR history, добавляя регрессии, метаданные версии и парные инструкции. ApplyConfigFile(ConfigFile&) и смысл runtime API, конфигурации, сети, ресурсов и маркеров совместимости сохраняются относительно родителя.
- Повторите конфигурацию и сборку метаданных версии и native unit executable, затем перегенерируйте EN/RU документацию, справочники/helper models, сайт/поиск/маршруты и AI delivery в порядке зависимостей. Выполните prepare, contract, format и точные version/history проверки.
- Повторно запустите AngelScript и Managed suites. Ошибки компиляции или подготовки не являются causal RED; baseline RED и candidate GREEN для неверного префикса должны исполнить одинаковые fixture и способы доставки. Реальный OS denial, Windows packages, staging/restart и rollback пока не квалифицированы.

## 2026.1.21-dev - 2026-10-10

### Исправлено

- Сократить парные пояснения scripting без изменения контрактов; уточнить порядок вызовов и проверки переводов, последовательность diagrams/reference, игнорируемые выходы, девятнадцать моделей описаний и автоматическое связывание Transform в обоих backend.
- Отформатировать migration-исходники.
- Enum-метаданные, заканчивающиеся на `= -`, отклоняются без чтения отсутствующего токена. Регрессия настоящего baker охватывает `.cs`/`.fos`, конец файла, перевод строки и комментарий.
- Native payload с неверным префиксом один раз скачивается с нулевого смещения в том же запуске. Полный неверный и слишком большой временный файл расходуют тот же повтор; отказ удаления и повторно неверная доставка остаются ошибкой без продвижения.
- Итоговая native-проверка заново читает размер и хеш всего файла; проверка resource pack и политика существующего PDB host сохранены.

### Тесты

- Добавлена общая регрессия с настоящими Updater/UpdaterBackend и secure channel для обоих способов доставки, смещений resume, границы повтора и освобождения terminal lock. Добавлена закрытая friend-only инъекция отказа очистки неверного partial, полного неверного и слишком большого native temp в обоих способах доставки; реальный отказ OS permissions проверяется отдельно.
- Добавлены профиль и CI-задание Managed, выполняющие RunUnitTests наряду с существующим набором AngelScript.

### Миграция

- Миграция API, конфигурации, сохранений, сети, ABI и формата ресурсов не требуется; кодирование допустимых enum, маркер совместимости и версия файла метаданных сохраняются.
- Завершите или удалите ошибочное объявление, пересоберите baker/метаданные версии; выполните `MetadataBakerRejectsTruncatedNegativeEnum`, прежние enum round-trip тесты и проектный bake метаданных для каждого backend. Перегенерируйте затронутую документацию и выходы доставки в порядке зависимостей.
- Выполните `python BuildTools/docs_prepare.py` и переконфигурируйте/пересоберите потребителей метаданных версии.
- Публичный API, конфигурация, сеть, сохранения, формат ресурсов, версия updater и ABI runtime не меняются. Пересоберите native-артефакты; сохраните границу generation-2/ABI-3 и продвижение при следующем запуске.
- Перегенерируйте метаданные версии, EN/RU переводы, справочники/helper models, сайт/поиск/маршруты и AI delivery. Выполните точный contract diff, оба native unit набора и приёмку Windows/пакетов перед квалификацией.

## 2026.1.18-dev - 2026-10-09

### Добавлено

- Добавлен `MigrationRule Property <Owner> Remove <Old>` как постоянный запрет имени. Старое значение в документе/тексте пропускается; живое объявление под этим именем отклоняется, включая поля RefType.
- Добавлена поддержка документных Property/Proto Transform в AngelScript: `[[PropertyMigrator]]`/`[[ProtoMigrator]]`, типизированное значение `&inout`, `const DatabaseDocument&inout`, автоматическая проверка исходников/байткода и связывание, синхронная атомарная подготовка результатов. Квалифицированное имя функции — `Namespace::Function`; AngelScript-скрипты нужно перепечь для нового зарегистрированного типа и callbacks. Массивы/словари RefType освобождаются путями своих контейнеров.

- Добавлены атомарные обработчики Property Transform: native `PropertyMigratorCallback`, Managed C# `[PropertyMigrator]`, `PropertyMigrator<T>` и контекст исходного `DatabaseDocument`. Канонические поля подготавливаются до загрузки сущности.

- Добавлены документные обработчики `[ProtoMigrator]` для Proto Transform. Цепочки исходного документа разрешаются до поиска с обнаружением циклов и подготовкой `_Proto`; обычный lookup и bake применяют только Rename/Remove.

### Изменено

- Правила переименования свойств требуют явного действия `Rename` и существующего назначения. `Transform` проверяет существование Persistent-свойства; серверные пользовательские владельцы и их правила следуют фильтрации роли метаданных.

### Миграция

- Для удалённого свойства сохраняйте `///@ MigrationRule Property Owner Remove Old` без замены. Rename и Transform остаются формами из пяти частей; Property и Proto Remove имеют четыре. Повторное имя запрещено независимо от нового типа свойства.
- Замените каждую декларацию `///@ MigrationRule Property Owner Old New` на `///@ MigrationRule Property Owner Rename Old New` в native/скриптовых исходниках, генераторах, инструментах и фикстурах. Старые имена должны указывать на существующие текущие поля, включая вложенные RefType. Старая форма из четырёх частей отклоняется; Правила Proto также требуют явного действия: Rename Old New, Remove Old или Transform Old QualifiedType.Function. Прежняя замена __remove__ отклоняется; Enum, Entity, EntityHolder и Version сохраняют формы.
- Для переноса значений задайте `///@ MigrationRule Property Owner Transform Property QualifiedType.Function` и статическую синхронную функцию с `[PropertyMigrator]`, результатом `bool` и параметрами `ref T`, `DatabaseDocument`, где `T` точно соответствует managed-типу свойства. `false` оставляет исходное представление, `true` сериализует результат. Нельзя сохранять контекст, менять сущности, выдавать награды или определять тип ссылки по совпадению текста. Проект задаёт смысловые условия, политику коллизий, идемпотентность и фикстуры старых сохранений/перезапуска. Managed C# связывает функции автоматически; несвязанная функция отвергает перенос.
- Пересоберите native-бинарники и выполните bake метаданных и всех managed-ролей вместе. Правила Property и Proto Rename/Transform содержат пять частей, Remove у обоих видов — четыре; внешний заголовок метаданных не меняется. Ручной маркер совместимости повышен с 68 до 69: смешанные старые/новые бинарники и ресурсы не поддерживаются. Схема БД, типы хранимых полей, сообщения транспорта, состав платформенных пакетов и поведение прочих свойств не меняются; добавленный native callback API требует пересборки встраивающих бинарников.
- Загрузка БД переносит Game, Player, обычные и пользовательские сущности, включая пакетные пути. Исключение при подготовке оставляет документ и очередь записи нетронутыми; гарантия относится к одному документу, не ко всем документам мира. Сохраняйте правила на поддерживаемый горизонт сохранений и проверьте копию БД перед production. Перегенерируйте API/справочник, snippets, переводы, сайт/поиск и данные для ИИ.

## 2026.1.17-dev - 2026-10-09

### Исправлено

- Существующие деревья READY, скачанные кэши workspace, готовые входы prebuilt и свежие опубликованные managed runtime проверяются по непустым embedding-заголовкам, основным managed-сборкам и входным архивам линковки выбранной платформы. Неполные деревья восстанавливаются существующим путём кэша/повторной публикации вместо сообщения о готовности runtime без нужных линкеру файлов.

### Миграция

- Миграция скриптового/native API, ключей конфигурации, сериализованных данных, сети, ABI, схем ресурсов и сохранений не требуется: изменение проверяет входы подготовки сборки и сохраняет смысл комплектных runtime. При переходе на эту ревизию Engine повторите конфигурацию и сборку native-метаданных версии и ревизии.
- Для восстановления неполного дерева READY запустите обычный target `SetupManagedRuntime` (либо BuildTools `setup-mono <os> <arch> <config>`). Без workspace-кэша действующие маркеры исходников/объектов позволяют повторить публикацию без перекомпиляции Mono; настроенный кэш принимает комплектные записи и пересобирает неполные попадания. Комплектные деревья сохраняют прежний ключ кэша и имена маркеров.
- `FO_MANAGED_RUNTIME_PREBUILT` должен указывать на комплектное дерево выбранной платформы: заголовки managed backend, CoreLib и `System.Runtime.dll`, статические архивы платформы и JavaScript glue браузера, если он нужен. Замените неполный prebuilt комплектным опубликованным деревом платформы; неполный вход отклоняется до копирования и записи READY. После обновления руководства перегенерируйте локализацию, сайт/поиск/маршруты, оценку ИИ и данные для ИИ.

## 2026.1.16-dev - 2026-10-09

### Изменено

- Авторская конфигурация Jekyll перенесена в `Docs/Site/_config.yml`. Файлы зависимостей Ruby/домена и публичные корневые endpoint генерируются в игнорируемом `Workspace/Documentation/`; `docs_site_build.py` собирает и экспортирует сайт в `Workspace/DocumentationSite/`. Публичные URL сохраняются.

- Индексы доставки документации и каталоги проверок создаются при сборке, а не коммитятся: `docs-manifest.json`, оба endpoints `llms`, навигация, поиск и шесть generated-отчётов. Вход сопровождающего с checkout остаётся `AGENTS.md`; сайт сохраняет публичные URL для получения документации.
- Документационные outputs подготавливаются перед проверкой CI и рендерингом сайта. Проверенный Pages artifact публикуется только после прохождения проверок версии и документации при push в master.

### Исправлено

- Значения Engine по умолчанию применяются до загрузки обычной конфигурации приложения. Настройки, пропущенные в конфигурации проекта или пакета, получают defaults из `Settings.inc`; явные значения конфигурации, подконфигурации, локального кэша и командной строки сохраняют прежний приоритет, включая явно заданные нули.

### Миграция

- Замените прямые команды Jekyll на `python BuildTools/docs_site_build.py`; после подготовки установите зависимости через `bundle install --gemfile Workspace/Documentation/Gemfile`. `Gemfile`, `.ruby-version` и `CNAME` выводятся из исходного manifest и больше не хранятся в корне как версионируемые копии.

- Перед локальными проверками документации или Jekyll выполните `python BuildTools/docs_prepare.py`. Модели публичных контрактов, Markdown, правила, переводы и SVG/PNG остаются версионируемыми и обязаны проходить freshness checks. Игнорируемые результаты доставки не добавляются в индекс.
- Перед первым push в master с этой правкой выберите GitHub Actions источником сборки Pages; прежняя сборка из ветки не может создать игнорируемые файлы. Проверьте первый опубликованный артефакт и существующие публичные endpoints. Правка рабочего дерева не переключает удалённые настройки и не публикует сайт.
- Повторите конфигурацию и сборку затронутых нативных приложений, затем bake и проверку профилей запуска встраивающего проекта. Проверьте ранее пропущенные настройки: теперь они получают объявленные defaults вместо нулей от инициализации значением. Имена настроек и объявленные defaults не меняются, явные значения сохраняют смысл.
- Нативный и скриптовый API, сетевая совместимость `0.0.68`, ABI, схемы ресурсов и сохранённые данные не меняются. Преобразование исходников проекта или сохранённых данных не требуется.

## 2026.1.15-dev - 2026-10-09

### Изменено

- Маршруты и отчёт переводов объединены в `docs-manifest.json`. Навигация и данные для ИИ ссылаются на `VERSION`; сборка Jekyll читает его значение вместо хранения копий версии. Поиск исключает технические HTML-комментарии, а полный контекст для ИИ оставляет хэши документов в публичном индексе.

### Миграция

- Потребители документации должны заменить `Docs/generated/document-routes.json` на `docs-manifest.json#/routing`, а `Docs/generated/translation-status.json` — на `docs-manifest.json#/translation_status`. Это разделы JSON одного файла, а не пути файловой системы. Схема данных для ИИ — `3`, схема сайта — `4`; смысл полей отчётов и хэши проверки переводов сохраняются. Прежние отдельные отчёты удалены.
- Перегенерируйте локализацию, сайт/поиск/маршруты, оценку ИИ при необходимости, затем данные для ИИ. Шаблон Jekyll включает `VERSION` напрямую; сохраняйте `includes_dir: .` в `_config.yml` для локальной сборки и GitHub Pages. Публикуйте корневой `VERSION` побайтно. Миграция native/скриптового API, конфигурации, сериализованных данных, сети, ABI, схем ресурсов и сохранений не нужна.
- При переходе на эту ревизию Engine повторите конфигурацию и сборку native-метаданных версии и ревизии.
