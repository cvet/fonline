# Форматы шрифтов и компоновка текста

FOnline рисует текст только TrueType-лицами. Клиент растеризует лица во время
выполнения через FreeType и привязывает их к слотам `FontType`; лица копируются в
запечённые ресурсы без изменений и не требуют изображения. Engine поставляет
шрифт по умолчанию, которым может рисовать даже голый исполняемый файл, и
конвертер, превращающий созданные bitmap-шрифты (`.fofnt` или бинарный BMFont) в
TrueType-лица. Клиент не загружает дескрипторы bitmap-шрифтов.

Используйте это руководство для решений по авторингу и интеграции. Точный
контракт текущей ревизии приведён в сгенерированном
[справочнике font-format](../../reference/font-format/index.md), на отдельных
страницах [форматов](../../reference/font-format/formats.md),
[привязки](../../reference/font-format/binding.md),
[авторинга](../../reference/font-format/authoring.md),
[компоновки](../../reference/font-format/layout.md),
[отрисовки](../../reference/font-format/rendering.md) и
[валидации](../../reference/font-format/validation.md), а также в
[канонической JSON-модели](../../../generated/font-format.json).

## Область и источники истины

Поведение определяют следующие исходники:

- `Source/Client/FontManager.cpp` и `.h`: привязка лиц, шрифт по умолчанию, листы
  глифов, компоновка текста, отрисовка и краткоживущий кэш форматирования;
- `Source/Client/FontRasterizer.cpp` и `.h`: обёртка над FreeType, которая
  открывает лица и растеризует буквы, включая цветные лица (сама библиотека
  лежит в `ThirdParty/freetype`);
- `Source/Scripting/ClientGlobalScriptMethods.cpp`: `Game.BindFont`,
  `Game.GetTextInfo`, `Game.GetTextLines` и `Game.DrawText`;
- `Source/Common/ResourceDefaults.h`: путь и размер шрифта по умолчанию;
- `Source/Common/Settings.inc` и `Source/Tools/RawCopyBaker.cpp`: выбор и доставка
  raw-copy;
- `BuildTools/bitmap_font_to_ttf.py`: конвертер bitmap-шрифтов;
- `Resources/Embedded/Fonts/` и `Resources/Core/Fonts/`: поставляемые лица.

`BuildTools/FontFormatInterface.json` — структурированный контракт на основе
исходников. `BuildTools/docs_font_format.py` выводит из живого кода перегрузку со
списком лиц, значения raw-copy по умолчанию, привязку шрифта по умолчанию,
значение ёмкости Embedded по умолчанию, флаги загрузки цветных лиц, константы
конвертера, слоты и флаги шрифтов, атлас, срок жизни кэша и перечень
поставляемых лиц. Он отклоняет расхождение исходников и манифеста и строит
сгенерированный справочник.

Эта страница — переиспользуемая документация Engine. Файлы шрифтов, расширения
`FontType`, назначения в GUI, типографика, языковое покрытие, лицензии, снимки
backend и пороги приёмки принадлежат встраивающему проекту. Проектные документы
могут ссылаться сюда, но не должны переопределять контракт привязки.

## Поддерживаемые ресурсы

| Суффикс | Роль в runtime | Примечания |
| --- | --- | --- |
| `.ttf` | TrueType-лицо | Единственный runtime-формат текста; привязывается перегрузкой `Game.BindFont` со списком лиц. |
| `.fofnt`, `.fnt` | Нет | Авторские источники [конвертера](#конвертация-bitmap-шрифтов); клиент их не загружает, а по умолчанию они не копируются raw-copy. |
| `.bmfc` | Нет | Конфигурация инструмента BMFont; не runtime-формат и не формат конвертера. |

Клиент не загружает дескрипторы bitmap-шрифтов, текстовые и XML-дескрипторы
BMFont, шрифты OpenType с контурами CFF и файлы WOFF. Преобразуйте такие
источники до поставки. Передача пути `.fofnt` или `.fnt` в список лиц обрывает
привязку: файла нет в запечённых ресурсах, если проект не копирует этот суффикс
raw-copy, а доставленный файл FreeType не может открыть как лицо.

Доставка лиц — это raw-copy:

1. Оставляйте `ttf` в `Baking.RawCopyFileExtensions`; значение по умолчанию —
   `ttf ogv json ini`. `RawCopyBaker` сохраняет байты и путь ресурса каждого лица.
2. Кладите лица в пакет ресурсов по пути, который привязывает скрипт.
3. Привязывайте слот на клиенте до того, как любой код измеряет или рисует им.

Успешное raw-copy запекание доказывает только доставку лица. Оно не доказывает
покрытие глифов, хинтинг, языковую поддержку или композицию GUI.

## Шрифт по умолчанию

Клиент, Mapper и встроенный обновлятор привязывают `Fonts/FOnline-Regular.ttf` к
`FontType::Default` размером 10 пикселей до запуска любого скрипта: с обычным
хинтингом, контуром в один пиксель для `FontFlag::Bordered` и диапазонами
предзагрузки `32-126`, `160-255` и `1024-1279` (латиница, Latin-1, кириллица).
Привязка пропускает уже привязанный слот, поэтому голый исполняемый файл рисует
текст сразу, а скрипт, сам привязывающий `Default`, просто заменяет шрифт.

Лицо — это преобразованный пиксельный шрифт FOnline, и лежит оно в пакете
ресурсов **Embedded** (`Resources/Embedded/Fonts/`), который вкомпонован в
исполняемый файл; именно его сжатый размер — причина, по которой
`FO_EMBEDDED_DATA_CAPACITY` теперь по умолчанию равен `400000`. Проект,
задающий собственную ёмкость, должен убедиться, что сжатый пакет Embedded по-
прежнему помещается.

Чтобы изменить вид по умолчанию:

- привяжите другие лица к `FontType::Default` из клиентского скрипта через
  `Game.BindFont` (повторная привязка пересобирает слот); или
- поставляйте собственный `Fonts/FOnline-Regular.ttf` в пакете ресурсов, который
  перекрывает пакет Engine: так стартовый шрифт до скриптов и обновлятор остаются
  согласованными.

Лицо должно содержать букву пробела и кодовые точки ваших текстов; лицо без
пробела обрывает привязку, а отсутствующий ресурс обрывает запуск.

## Привязка слотов шрифта

Engine объявляет один слот:

```angelscript
enum FontType
{
    Default = 0
}
```

Встраивающий проект может расширить `FontType` через аннотацию codegen enum и
привязать каждый дополнительный слот при инициализации клиента:

```angelscript
void BindFonts()
{
    int[] ranges = {32, 126, 160, 255, 1024, 1279};

    string[] fat = {"Fonts/FOnline-Fat.ttf"};
    Game.BindFont(FontType::Fat, fat, 16, FontOptions(), ranges);

    string[] numbers = {"Fonts/FOnline-Numbers.ttf"};
    Game.BindFont(FontType::Numbers, numbers, 17, FontOptions(), ranges);
}
```

Точный синтаксис расширения enum определяется настройкой генерируемого API
встраивающего проекта. Слоты — целочисленные индексы, а не алиасы путей.
Измерение или рисование незагруженным, отрицательным или выходящим за диапазон
слотом бросает исключение.

У `Game.BindFont` одна перегрузка: список лиц, размер в пикселях, `FontOptions` и
диапазоны предзагрузки. Она привязывает к `AtlasType::IfaceSprites`. Повторная
привязка слота заменяет его шрифт, освобождает прежний лист глифов и очищает
кэшированные раскладки. Шрифт движка по умолчанию занимает `FontType::Default`,
пока скрипт не привяжет слот заново.

Масштаба при привязке нет. Выбирайте размер в пикселях, который хотите видеть:
TrueType-лицо масштабируется через контуры, а лицо, преобразованное из
bitmap-шрифта, точно в своём родном размере (см.
[Конвертация bitmap-шрифтов](#конвертация-bitmap-шрифтов)).

## TrueType-шрифты

`Game.BindFont(font, faces, pixelSize, options, preloadRanges)` привязывает слот
к TrueType-лицам, которые растеризует FreeType. Повторный вызов для того же
слота пересобирает шрифт другого размера, с другими лицами или параметрами и
освобождает прежний лист глифов в атласе. Вызывающий сам перекомпоновывает
кэшированный текст, потому что измерения зависят от шрифта.

- **Лица** образуют цепочку запасных путей к файлам шрифтов. Буква берётся из
  первого лица, где она есть. Буква, которой нет ни в одном лице, рисуется
  рамкой отсутствующего глифа первого лица, причём все такие буквы делят одну
  ячейку, поэтому пробел в покрытии виден, а строка не укорачивается молча.
  `FontManager::HaveLetter` отвечает по лицам и рамку никогда не сообщает.
- **Буквы растеризуются при первом использовании.** `preloadRanges` (включённые
  пары кодовых точек) растеризуются при привязке, чтобы первые кадры с ними не
  задерживались; кодовые точки диапазона, которых нет ни в одном лице,
  пропускаются. Любая другая буква растеризуется, когда текст с ней впервые
  измеряют или рисуют, поэтому запросы измерения (`GetTextInfo`,
  `GetLinesCount`, `GetLinesHeight`) не являются const. Управляющие символы
  служат командами компоновки и глифами не становятся.
- **Одна текстура на шрифт.** Ячейки глифов укладываются полками в один лист на
  шрифт, второй лист нужен для варианта с контуром. Заполненный лист
  удваивается, сохраняет все ячейки на месте, загружается как новый спрайт
  атласа, а старый освобождается после сброса очереди текста. Лист не больше
  2048 на 2048 пикселей.
- **Метрики остаются целыми и одинаковыми на всех платформах.** FreeType
  работает в формате 26.6; продвижения и кернинг округляются до целых пикселей,
  а высота строки равна сумме подъёма и спуска лица при данном размере. Поэтому
  клиенты Windows и web переносят один и тот же текст в одном месте.
- **Перенос продвигается и в узком поле.** Слишком большой первый глиф занимает
  свою строку, а измерение сообщает его фактическую ширину, чтобы вызывающий мог
  обнаружить переполнение. Явные флаги усечения по-прежнему отбрасывают текст,
  не поместившийся в поле.
- **`FontOptions`** (нулевое значение: лёгкий хинтинг, сглаживание, без кернинга
  и контура): `Hinting` (`Light` — автоматический хинтинг только по вертикали,
  `Normal` — полный хинтинг по инструкциям самого шрифта, где они есть,
  `Unhinted` — контуры как нарисованы), `Monochrome` (бинарное покрытие, 0 или
  255), `ForceAutoHint` (автохинтер FreeType вместо родных инструкций;
  `Unhinted` отключает оба), `Embolden` (искусственный полужирный: покрытие
  расширяется на пиксель вправо, к каждому продвижению, включая пробелы,
  добавляется пиксель; лучше взять настоящее жирное лицо), `Kerning` (парный
  кернинг из таблицы `kern` или простых пар GPOS между соседними буквами одного
  лица, одинаково при измерении и рисовании), `OutlineWidth` (пиксели тёмного
  контура, который рисует `FontFlag::Bordered`; ноль рисует для этого флага
  обычные глифы), `LineSpacing` (пиксели, добавляемые к межстрочному
  промежутку лица; значение может быть отрицательным, но шаг строки должен
  оставаться положительным).

Шейпинга текста нет: текст раскладывается по одному глифу на кодовую точку слева
направо. Латиница, кириллица, греческий, армянский, грузинский, CJK и символы
отображаются верно; письменности, которым нужны шейпинг или двунаправленная
компоновка (арабская, иврит, индийские, тайская), комбинируемые диакритические
знаки и лигатуры — нет.

Сборка FreeType включает только драйвер TrueType, загрузчик SFNT, автохинтер,
серый и монохромный растеризаторы и цветные слои TrueType (`COLR` версии 0 поверх
`CPAL`): шрифты OpenType с контурами CFF, файлы WOFF и экземпляры вариативных
шрифтов, кроме заданного по умолчанию, не поддерживаются, а переменная окружения
`FREETYPE_PROPERTIES` не читается. Размер ограничен 256
пикселями, контур — 8 пикселями. Модульные тесты Engine `Test_FontRasterizer` и
`Test_FontManager` растеризуют тестовые шрифты, сгенерированные из прямоугольников
скриптом `BuildTools/generate_test_fonts.py`, поэтому каждая проверяемая метрика
следует из чисел этого скрипта.


## Цветные шрифты

Лицо с цветными слоями `COLR` v0 поверх палитры `CPAL` рисует каждый глиф
собственными цветами. Растеризатор загружает такое лицо с `FT_LOAD_COLOR` и без
хинтинга и рисует его со сглаживанием в цветной растр, поэтому опции
`Monochrome`, `Hinting`, `ForceAutoHint` и `Embolden` к нему не применяются. Лист
глифов сохраняет цвета глифов с прямой альфой, шейдер шрифта умножает их на цвет
текста, а вариант с обводкой сохраняет цвета глифов под обводкой.

Шейдер шрифта считает цвет глифа, умноженный на цвет текста и на два, а обычный
глиф хранится нейтральным серым 128, поэтому рисуется цветом текста без
изменений. Цвет текста нейтрального серого (128, 128, 128) показывает цветное
лицо как задумано; любой другой цвет текста тонирует или осветляет его.
Поставляемые числовые лица `FOnline-Numbers.ttf`, `FOnline-BigNumbers.ttf` и
`FOnline-SandNumbers.ttf` цветные.

## Конвертация bitmap-шрифтов

`BuildTools/bitmap_font_to_ttf.py` превращает созданный bitmap-шрифт в
TrueType-лицо. Он читает текстовый дескриптор `.fofnt` с изображением или
бинарный BMFont v3 `.fnt` с единственной страницей и требует `fontTools`, Pillow,
`numpy` и `potracer`; ни runtime, ни документационные gate в них не нуждаются.

```powershell
python BuildTools\bitmap_font_to_ttf.py SOURCE.fofnt OUTPUT.ttf --family "Name" --style Regular
python BuildTools\bitmap_font_to_ttf.py SOURCE.fofnt OUTPUT.ttf --family "Name" --style Regular --check
```

- **Метрики.** Один пиксель bitmap — 100 единиц шрифта, а родной размер в
  пикселях — шаг строки шрифта: `LineHeight + YAdvance` для `.fofnt`. Привязывайте
  преобразованное лицо в этом размере, чтобы воспроизвести компоновку bitmap.
  Родной размер вне диапазона 1..255 отклоняется. Глифов для управляющих кодов в
  лице нет; задайте в источнике явную букву пробела, потому что клиент отвергает
  лицо без неё.
- **Одноцветные шрифты** встраивают bitmap как 8-битный страйк `EBDT`/`EBLC` в
  родном размере, который FreeType рисует пиксель в пиксель при любом режиме
  растеризации и хинтинга, и несут контуры, трассированные по покрытию глифов,
  для всех остальных размеров. Пустая программа `prep` не даёт FreeType
  автоматически хинтовать лицо.
- **Многоцветные шрифты** (источник с цветами помимо нейтрального серого)
  становятся слоями `COLR` v0 поверх палитры `CPAL`: по одному слою на каждый
  различный цвет пикселя из целопиксельных прямоугольников, точные в родном
  размере и масштабированная пиксельная сетка в других. Базовыми глифами служат
  трассированные силуэты.
- **Детерминированный результат.** Метки времени зафиксированы, поэтому второй
  запуск пишет те же байты. `--check` преобразует в памяти и завершается ошибкой,
  если `OUTPUT` отсутствует или отличается от свежего преобразования, поэтому
  закоммиченное лицо, переставшее соответствовать источнику, обнаруживается.

В дереве Engine лежат только конвертер и сгенерированные лица. Исходные
bitmap-источники лиц, которые поставляет Engine, хранятся вне него, в репозитории
`fonline-historical-stuff` (папка `FontSources`); это указатель для
происхождения, а не зависимость сборки. Проект, владеющий bitmap-шрифтом,
поступает так же: хранит источник вне любого пакета ресурсов, коммитит
сгенерированное лицо и запускает `--check` с этим источником в своей валидации.

## TextFormat и компоновка

`TextFormat` содержит `Font`, битовую маску `FontFlag` и неотрицательный
`SkipLines`. Точные значения флагов перечислены в сгенерированном
[справочнике компоновки](../../reference/font-format/layout.md). Важные
взаимодействия:

- по умолчанию при конечной ширине строка переносится по последнему пробелу или
  табуляции; слишком длинный токен разрывается в точке переполнения;
- `NoWrap` обрывает отрисовку при первом переполнении ширины. Это режим только
  отрисовки: `Game.GetTextInfo` продолжает обычный перенос, поэтому измерение не
  определяет итоговую обрезанную подстроку;
- `TruncateLine` удаляет переполняющие глифы до следующего авторского перевода строки;
- `CenterX` и `AlignRight` позиционируют каждую строку независимо;
- `CenterY` и `AlignBottom` позиционируют видимый блок текста по вертикали;
- `SkipLines` удаляет начальные строки, а с `AlignBottom` конечные;
- `KeepTail` удаляет начальное переполнение, сохраняя новые помещающиеся строки;
- `Justify` распределяет оставшуюся ширину между пробелами перенесённых строк.
  Табуляции остаются равными четырём ширинам пробела;
- `Bordered` выбирает сгенерированную текстуру с обводкой.

Нулевая ширина или высота для форматировщика означает отсутствие ограничения
по соответствующему измерению. Публичные функции подсчёта строк отклоняют
неположительные размеры, поэтому для переносимого измерения используйте явно
положительные прямоугольники GUI.

Форматировщик декодирует кодовые точки UTF-8. Некорректные последовательности
имеют нулевое продвижение и не дают глифа. Корректная буква, которой нет ни в
одном привязанном лице, рисуется рамкой отсутствующего глифа первого лица, поэтому
пробел в покрытии виден. Покрытие глифов по-прежнему должно быть отдельным
проектным gate.

## Измерение и отрисовка

При измерении и отрисовке используйте один слот, флаги, ширину и высоту:

```angelscript
TextFormat format;
format.Font = FontType::Default;
format.Flags = FontFlag::CenterX | FontFlag::CenterY;

isize resultSize;
int resultLines;
Game.GetTextInfo(text, boxSize, format, resultSize, resultLines);
Game.DrawText(text, boxPos, boxSize, color, format);
```

`Game.DrawText` доступен только в событии отрисовки интерфейса. Отрицательная
ширина или высота сдвигает начало прямоугольника и преобразуется в положительный
размер до компоновки. Прозрачный цвет выбирает стандартный белый цвет текста Engine.

За исключением `NoWrap`, действующего только при отрисовке, измерение и отрисовка
используют один форматировщик, метрики строк, пропуски и продвижения глифов. `GetTextInfo` возвращает максимальную ширину строки, высоту видимого
блока и число видимых строк. Ключ кэша включает текст, слот, флаги, пропуски,
размеры прямоугольника, цвет и режим форматирования; записи истекают после трёх
неиспользованных кадров и сбрасываются при замене шрифта. Не полагайтесь на
идентичность или срок жизни кэша.

## Цвет и эффекты

Шрифт начинает работу с общим эффектом шрифта Engine. Проект может заменить
общий эффект или выбрать подтип `EffectType::Font` для отдельного слота. Пустое
переопределение слота возвращает его к текущему общему эффекту. Синтаксис и
backend-валидация описаны в [формате эффектов](effect-format.md).

Цветные лица рисуют собственные цвета, умноженные на цвет текста (см.
[Цветные шрифты](#цветные-шрифты)). Встроенные теги отрисовщика используют упакованный порядок Engine `BBGGRR` /
`AABBGGRR` с необязательным префиксом `0x`; `@color@` восстанавливает предыдущий
цвет. Корректные теги удаляются до переноса. При `NoColorize` они также удаляются,
но цвет не применяется. Некорректные теги остаются обычным текстом. Точные формы
и общая граница авторинга строк описаны в
[тексте и локализации](text-and-localization.md#граница-форматирования-engine-и-проекта);
не дублируйте эти теги в проектной грамматике локализации.

## Рекомендуемые проектные практики

Держите типографику компактной и управляемой данными:

1. Определяйте семантические слоты для основного текста, заголовков, компактных
   чисел и отладки, а не отдельный слот для каждого виджета.
2. Привязывайте каждый слот в проверенном размере в пикселях; преобразованное
   пиксельное лицо точно в родном размере. Не рассчитывайте на масштабирование
   при компоновке.
3. Включайте все кодовые точки основного и запасного языков, пунктуацию, цифры
   и символы, используемые игровым процессом, чатом, консолью и обновлятором.
4. Проверяйте в одной области review лицо, расположение его bitmap-источника, если
   оно преобразовано, сведения о лицензии и происхождении, привязку слота и
   визуальную тестовую сцену.
5. Измеряйте динамические подписи с реальной локализованной строкой и слотом;
   не рассчитывайте панель по английской заглушке или числу символов.
6. Поддерживайте матрицу снимков обычной/обведённой отрисовки, всех привязанных размеров в пикселях,
   узкого переноса, используемых выравниваний и самых длинных локализованных
   подписей на каждом поддерживаемом backend.

## Процесс валидации

После изменения привязки лиц, метрик, компоновки, конвертера или скриптовой
привязки Engine:

```powershell
python BuildTools\docs_font_format.py --write
python -m unittest BuildTools.tests.test_docs_font_format
python -m unittest BuildTools.tests.test_bitmap_font_to_ttf
python BuildTools\docs_contract_diff.py --check
cmake --build <build-dir> --config RelWithDebInfo --target RunUnitTests
```

После изменения шрифта во встраивающем проекте:

1. Перегенерируйте проектный код при изменении `FontType`.
2. Запеките лица и, если проект преобразует bitmap-шрифты, сначала запустите
   `--check` конвертера.
3. Запустите целевые тесты измерения текста и компоновки GUI для каждого
   изменённого слота или размера в пикселях.
4. Откройте видимый клиент и проверьте обычные, обведённые, цветные,
   перенесённые, выровненные и локализованные строки.
5. Проверьте журналы на исключения лица, атласа, эффекта и скрипта.
6. В том же изменении обновите проектный каталог шрифтов и документацию GUI/локализации.

Целевые сгенерированные проверки доказывают описанный контракт исходников.
Только встраивающий проект может доказать покрытие глифов, типографику, посадку
в UI, поведение backend отрисовки и права на ресурсы.
